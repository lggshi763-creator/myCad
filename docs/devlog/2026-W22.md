## 架构亮点

### SqliteEventStore — 序列化与 loadRows 分层

payload 在 `append()` 时通过 `SerializerFn` 写入 SQLite，`load()` 只用 `EventTypeRegistry` 重建元数据 shell。payload-aware 重放走 `loadRows()` → 上层（MainWindow）负责解析 JSON + 重建几何。这避免了"把 OCCT 依赖拖入 store"的分层污染。

`allAggregateIds()` 用 `SELECT DISTINCT aggregate_id`，File → Open 的全量重放不需要提前知道任何聚合 ID。

### MycadFileStore — ZIP RAII + 两步写入

`ZipGuard` 封装 `zip_t*`，失败路径调用 `zip_discard()`，成功路径 `release()` 后 `zip_close()`：

```
save():  zip_open(CREATE|TRUNCATE) → manifest.json(buffer) → events.db(file) → zip_close
load():  zip_open(RDONLY) → zip_stat → zip_fopen → zip_fread → ofstream 写出
```

manifest.json 用 `SQLITE_TRANSIENT`（`freep=0`）绑定缓冲区，`manifest` 字符串在 `zip_close` 前一直存活。

### GL context cleanup — aboutToBeDestroyed 模式

```
initializeGL()
  └─ connect(context(), &QOpenGLContext::aboutToBeDestroyed,
             this, &ViewportWidget::onContextAboutToBeDestroyed,
             Qt::DirectConnection)

onContextAboutToBeDestroyed()
  └─ makeCurrent() → adapter_->cleanup() → doneCurrent()

cleanup()
  └─ freeMeshEntry × N → meshes.clear()
  └─ freeMeshEntry(testTriangle)
  └─ glDeleteProgram → initialized = false
```

`Qt::DirectConnection` 保证 slot 在 context 线程同步执行，不会被 event loop 延迟。`cleanup()` 幂等（`initialized` 标志保护），析构函数保留调用作为非 GUI 场景的 safety net。

### 逐顶点法线 — 面法线累加算法

```
for each triangle (i0, i1, i2):
    e1 = p1 - p0;  e2 = p2 - p0
    face_normal = e1 × e2          // 不归一化，幅值 ∝ 面积（area weighting 自动）
    normals[i0] += face_normal
    normals[i1] += face_normal
    normals[i2] += face_normal
for each vertex v:
    normals[v] = normalize(normals[v])   // |len| < 1e-6 的退化顶点跳过
```

未归一化的叉积幅值正比于三角形面积，因此大面贡献更重——这是"面积加权平均"的最简实现，无额外代价。
