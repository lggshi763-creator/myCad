## 技术亮点

### OCCT PIMPL 落地

`OcctGeometryAdapter.hpp` 仅依赖 `<mycad/domain/IGeometryConstructionPort.hpp>` 和标准库。所有 OCCT 类型（`TopoDS_Shape`、`Bnd_Box`、`Poly_Triangulation` 等）藏在 `OcctGeometryAdapter.cpp` 中的匿名 `Impl` 结构体里。CI 的 Tier-B grep 步骤验证该约束（ADR-0004 V6）。

`tessellate` 实现要点：
- `BRepMesh_IncrementalMesh` 构造即触发网格化，无需显式调用 `Perform()`
- `Poly_Triangulation` 节点 1-based，转换为 0-based 时要加 `vertBase` 偏移
- `TopAbs_REVERSED` 面需 `swap(n1, n2)` 保证法向一致

### EnTT 模板 vs PIMPL 的权衡

`emplace<T>/tryGet<T>/remove<T>` 是模板，函数体必须在头文件可见，无法用 PIMPL 完全隐藏 `entt::registry`。决策：直接在 `.hpp` 中 `#include <entt/entt.hpp>` 并将 `entt::registry` 作为成员。ADR-0007 约束（"entt 实例不离开 infrastructure/ecs/"）仍然满足——domain/application 代码依赖的是 `IEntityRegistry` 接口，永远不会 `#include` `EnttRegistry.hpp`。

`size()` 用 `aliveCount_` 手动计数，因为 EnTT 存储内部的 free list 大小不在公开 API 中。

### InMemoryEventStore 序列化策略

Sprint 0.3 中 `payload` 字段为空串占位，序列化仅存储 `{typeName, aggregateId, aggregateVersion, occurredAtMs}`。反序列化通过 `EventTypeRegistry::instance().findFactory(typeName)` 重建事件对象。Sprint 0.5 计划换 FlatBuffers（见 ADR 候选 ADR-0015）。

### C++23 `std::expected` 升级

`cxx_std_20` → `cxx_std_23`（`src/domain/CMakeLists.txt`），以启用 `<expected>` 用于 `GeomResult<T>`。VS 18（2026）在 `/std:c++23preview` 下完整支持。
