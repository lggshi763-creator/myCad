# mycad-style-check

## When to invoke

**Auto-invoked** by [.claude/settings.local.json](../../../.claude/settings.local.json) PostToolUse hook on every Edit/Write to `*.cpp` / `*.hpp` / `*.h` / `*.cc` / `*.cxx` / `*.hxx` / `*.inl` / `*.ipp`.

**Manual triggers**:
- User says: "style check / 检查这个文件 / mycad-style / Doxygen 检查"
- Before submitting a PR / preparing a commit
- After AI generates a new C++ file (especially when generated by another agent like DeepSeek)

## Procedure

1. **Run** [tools/check-style.ps1](../../../tools/check-style.ps1) on the changed file(s):
   ```bash
   pwsh -File tools/check-style.ps1 -Path <file>
   # or for multiple files:
   pwsh -File tools/check-style.ps1 -Path src/domain/shared/**/*.hpp
   ```

2. The script checks **3 layers**, in order:

   ### Layer 1 — clang-format (formatting)
   ```bash
   clang-format --style=file --dry-run --Werror <file>
   ```
   - Violations: indentation, line length, brace style, etc.
   - Fix: `clang-format -i <file>`

   ### Layer 2 — clang-tidy (lint)
   ```bash
   clang-tidy <file> --quiet
   ```
   - Violations: bugprone-*, modernize-*, readability-* etc.
   - Fix manually or with `--fix` (review carefully — auto-fixes can be invasive).

   ### Layer 3 — Doxygen comment convention (mycad-specific)
   - All public symbols (in headers) must have `///` Doxygen comments (NOT `/** */`)
   - Comment block must contain `@brief` (and brief should be in English, ASCII-only first line)
   - Functions taking parameters must have `@param <name>` for each
   - Functions returning non-void should have `@return`
   - Functions that can throw should have `@throws <ExceptionType>`
   - File-level comment block (when present) uses `@file`
   - **Spec source**: [CLAUDE.md §2.3](../../../CLAUDE.md), sample at [src/domain/shared/include/mycad/domain/Hello.hpp](../../../src/domain/shared/include/mycad/domain/Hello.hpp)

3. **Report violations clearly** so the AI can fix them. Format:
   ```
   [style] <file>:<line>: <issue>
     why: <one-line rule reference>
     fix: <suggested fix>
   ```

4. **Self-fix** if the AI just generated the file:
   - clang-format violations → run `clang-format -i` on the file
   - Missing `@brief` / wrong comment style → re-edit the file
   - clang-tidy issues → consider, fix in the same turn if obvious; flag for user if controversial

5. **When triggered by hook auto** (PostToolUse): the AI sees the hook output but doesn't have to act immediately if the user is mid-conversation about something else. Aggregate violations until natural stopping point, then offer to fix.

## What "Doxygen check" specifically inspects

A header file like `src/<layer>/<module>/include/mycad/<layer>/Foo.hpp` must:

| Check | Pattern |
|---|---|
| Comment style | All comments before public-facing types/functions are `///`, not `/** */` |
| Has `@brief` | Each documented entity has `@brief` (or AUTOBRIEF auto-applied via JAVADOC_AUTOBRIEF, but explicit is preferred) |
| `@brief` is English | First non-whitespace line of brief is ASCII; doesn't contain CJK characters in the brief itself |
| Has `@param` for each parameter | Function decl has `(T1 a, T2 b)` → comment must have `@param a` and `@param b` |
| Has `@return` for non-void returns | Detected from declaration |
| Has `@throws` if function can throw | Heuristic: if function body uses `throw` / `new` / unbounded allocation, expect `@throws` |
| Detail in Chinese OK | Lines after `@brief` and blank line can be Chinese |

The script can use simple regex for layers 1-3 — sophisticated parsing isn't needed for skeleton. Strict-but-fair, not nitpicky.

## False positives to ignore

- `placeholder.cpp` / `placeholder_test.cpp` — these intentionally lack docs, exempt
- Files generated by Qt MOC / RCC / UIC — these have `moc_*.cpp` / `qrc_*.cpp` / `ui_*.h` patterns, exempt
- Test files with `TEST_CASE(...)` — Catch2 test cases don't need Doxygen

## Anti-patterns

- ❌ Don't fail loudly on layer 3 if layer 1 already failed — fix formatting first, re-run
- ❌ Don't auto-fix layer 2 (clang-tidy) without review — `modernize-*` can change semantics
- ❌ Don't refuse to commit — pre-commit hook (Git) is the gate; this skill is advisory
